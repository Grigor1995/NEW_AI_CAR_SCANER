# Architecture decisions

1. **Fresh implementation:** V3 explicitly supersedes source reuse. Preserve Git history and an archive; remove old active code and pipelines. No legacy application code is copied.
2. **C++20/Qt 6.8:** one domain library and QML client, distinct per-platform builds; Qt 6.8 supports the tested responsive layout and module tooling.
3. **Qt HTTP host initially:** Qt HttpServer keeps local transport/event-loop/toolchain integration small. Drogon was recommended, not mandated. Reevaluate for hardened public deployment; the current host is loopback-only.
4. **SQLite first, PostgreSQL planned:** a tested local durable identity/settings/profile slice precedes remote persistence. No fake PostgreSQL connection or cross-device sync.
5. **Fail-closed writes:** implement testable safety policy, keep actual ECU writes locked until operation-specific hardware profiles, confirmation/audit executor and bench verification exist.
6. **Explicit feature status:** disabled/unavailable future pages contain no invented data, provider health or active payment actions.
7. **Qt translation catalogs:** exactly EN/HY/RU/FR with live retranslation and engineering units preserved internally.
8. **No CI/CD:** all evidence is generated by local executable builds/tests.

## Reference launcher and deterministic controls (UI correction)

The user supplied the original launcher screenshot as the required visual target.
Restore only its three project visual assets under assets/launcher: background,
3D sprite atlas and abstract vehicle. No old application code is restored. The
canonical installed app icon remains unchanged.

Select Qt Quick Controls Basic before QML loads, and use explicitly themed
Basic-derived buttons, combo boxes, inputs, spin boxes and dialogs. Windows'
default native white control surfaces did not honor the dark text palette
consistently; explicit surfaces/content colors remove that dependency. Menu and
combo popups use Popup.Item so application colors also govern popup contents.
